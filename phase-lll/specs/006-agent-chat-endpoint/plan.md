# Implementation Plan: OpenRouter Agent Integration & Chat Endpoint

**Branch**: `006-agent-chat-endpoint` | **Date**: 2026-02-10 | **Spec**: [spec.md](./spec.md)
**Input**: Feature specification from `/specs/006-agent-chat-endpoint/spec.md`

## Summary

Add a `POST /api/chat` endpoint that receives a user message, routes it through an AI agent configured via OpenRouter (OpenAI-compatible API), enables the agent to invoke MCP tools for task management, and persists the full conversation to the database. The implementation uses the standard OpenAI Python client pointed at OpenRouter's base URL, with MCP tools exposed as OpenAI function-calling definitions.

## Technical Context

**Language/Version**: Python 3.11+
**Primary Dependencies**: FastAPI, OpenAI Python SDK (`openai`), SQLModel, existing MCP tools
**AI Provider**: OpenRouter (`https://openrouter.ai/api/v1`)
**Default Model**: `anthropic/claude-3.5-sonnet` (via OpenRouter)
**Storage**: Neon Serverless PostgreSQL (existing)
**Testing**: Manual via Postman (POST JSON payloads, verify DB)
**Constraints**: Stateless per-request; no global conversation memory; user isolation via JWT
**Scale/Scope**: 1 new router, 1 agent service module, 1 config module, request/response schemas

### 1.2 Create Agent Service Module

**File**: `backend/app/agent.py` (NEW)

```python
import os
import json
from openai import OpenAI
from dotenv import load_dotenv

load_dotenv()

OPENROUTER_API_KEY = os.getenv("OPENROUTER_API_KEY")
OPENROUTER_BASE_URL = "https://openrouter.ai/api/v1"
DEFAULT_MODEL = "anthropic/claude-3.5-sonnet"

def get_openrouter_client() -> OpenAI:
    """Create OpenAI client configured for OpenRouter."""
    if not OPENROUTER_API_KEY:
        raise ValueError("OPENROUTER_API_KEY environment variable is required")
    return OpenAI(
        api_key=OPENROUTER_API_KEY,
        base_url=OPENROUTER_BASE_URL,
        default_headers={
            "HTTP-Referer": "https://todo-ai-chatbot.app",
            "X-Title": "Todo AI Chatbot",
        },
    )
```

**Rationale**:
- Standard `openai` Python SDK is fully compatible with OpenRouter's API
- `default_headers` include OpenRouter-specific headers (`HTTP-Referer`, `X-Title`) for attribution and rate-limit tracking
- Client instantiated per-call or as module-level singleton (stateless - no conversation state held)

## Phase 3: Agent Execution Logic

This is the core of the feature. The agent service handles the full request cycle.

### 3.1 Tool Definitions for OpenAI Function Calling

**File**: `backend/app/agent.py`

Convert MCP tools to OpenAI function-calling format:

```python
TOOL_DEFINITIONS = [
    {
        "type": "function",
        "function": {
            "name": "add_task",
            "description": "Create a new task for the user",
            "parameters": {
                "type": "object",
                "properties": {
                    "title": {"type": "string", "description": "Task title"},
                    "description": {"type": "string", "description": "Optional task description"},
                },
                "required": ["title"],
            },
        },
    },
    # ... similar for list_tasks, complete_task, delete_task, update_task
]
```

**Note**: `user_id` is NOT included in tool parameters exposed to the LLM. It is injected server-side from the authenticated user context. This prevents prompt injection attacks where a user could try to manipulate another user's tasks.

### 3.2 Tool Execution Dispatcher

**File**: `backend/app/agent.py`

```python
from app.mcp_tools import (
    add_task_impl, list_tasks_impl, complete_task_impl,
    delete_task_impl, update_task_impl,
)

TOOL_DISPATCH = {
    "add_task": add_task_impl,
    "list_tasks": list_tasks_impl,
    "complete_task": complete_task_impl,
    "delete_task": delete_task_impl,
    "update_task": update_task_impl,
}

def execute_tool(session, user_id, tool_name, arguments):
    """Execute an MCP tool with user_id injection."""
    fn = TOOL_DISPATCH.get(tool_name)
    if not fn:
        return error_response("not_found", f"Unknown tool: {tool_name}")

    # Inject user_id into arguments
    if tool_name == "add_task":
        return fn(session, user_id, arguments.get("title", ""),
                  arguments.get("description"))
    elif tool_name == "list_tasks":
        return fn(session, user_id)
    elif tool_name in ("complete_task", "delete_task"):
        return fn(session, user_id, arguments.get("task_id", ""))
    elif tool_name == "update_task":
        return fn(session, user_id, arguments.get("task_id", ""),
                  arguments.get("title"), arguments.get("description"))
```

**Rationale**: The dispatcher injects `user_id` server-side, ensuring user isolation. The `_impl` functions are reused directly from `mcp_tools.py`, avoiding code duplication.

### 3.3 Agent Run Function (Core Loop)

**File**: `backend/app/agent.py`

The main execution flow:

```python
def run_agent(session, user_id, user_message, conversation_id=None):
    """
    Full agent execution flow:
    1. Fetch or create Conversation
    2. Load Message history
    3. Save user message to DB
    4. Construct payload (system prompt + history + tools)
    5. Call OpenRouter API
    6. Handle tool calls (loop: execute tool -> send result -> get response)
    7. Save assistant response to DB
    8. Return response + conversation_id
    """
```

**Step-by-step detail**:

**Step 1 - Fetch/Create Conversation**:
```python
if conversation_id:
    conversation = session.exec(
        select(Conversation).where(
            Conversation.id == conversation_id,
            Conversation.user_id == user_id
        )
    ).first()
    if not conversation:
        raise ValueError("Conversation not found")
else:
    conversation = Conversation(user_id=user_id)
    session.add(conversation)
    session.commit()
    session.refresh(conversation)
```

**Step 2 - Load Message History** (last 50 messages for context window):
```python
statement = (
    select(Message)
    .where(Message.conversation_id == conversation.id)
    .order_by(Message.created_at)
    .limit(50)
)
history = session.exec(statement).all()
```

**Step 3 - Save User Message**:
```python
user_msg = Message(
    conversation_id=conversation.id,
    role="user",
    content=user_message,
)
session.add(user_msg)
session.commit()
```

**Step 4 - Construct API Payload**:
```python
messages = [{"role": "system", "content": SYSTEM_PROMPT}]
for msg in history:
    messages.append({"role": msg.role, "content": msg.content})
messages.append({"role": "user", "content": user_message})
```

**Step 5 - Call OpenRouter**:
```python
client = get_openrouter_client()
response = client.chat.completions.create(
    model=DEFAULT_MODEL,
    messages=messages,
    tools=TOOL_DEFINITIONS,
)
```

**Step 6 - Tool Call Loop**:
```python
assistant_message = response.choices[0].message

while assistant_message.tool_calls:
    # Add assistant message with tool calls to messages
    messages.append(assistant_message.model_dump())

    # Execute each tool call
    for tool_call in assistant_message.tool_calls:
        args = json.loads(tool_call.function.arguments)
        result = execute_tool(session, user_id,
                              tool_call.function.name, args)
        messages.append({
            "role": "tool",
            "tool_call_id": tool_call.id,
            "content": result,
        })

    # Get next response from LLM
    response = client.chat.completions.create(
        model=DEFAULT_MODEL,
        messages=messages,
        tools=TOOL_DEFINITIONS,
    )
    assistant_message = response.choices[0].message
```

**Step 7 - Save Assistant Response**:
```python
assistant_msg = Message(
    conversation_id=conversation.id,
    role="assistant",
    content=assistant_message.content,
)
session.add(assistant_msg)
session.commit()
```

**Step 8 - Return**:
```python
return assistant_message.content, conversation.id
```

### 3.4 Error Handling

**File**: `backend/app/agent.py`

Wrap the agent run in try/except:

```python
from openai import APIError, APIConnectionError, RateLimitError

try:
    response_text, conv_id = run_agent(...)
except (APIError, APIConnectionError):
    # OpenRouter unavailable
    return ChatResponse(
        response="I'm having trouble connecting right now. Please try again.",
        conversation_id=conversation_id or new_id,
    )
except RateLimitError:
    # Rate limited by OpenRouter
    return ChatResponse(
        response="I'm receiving too many requests. Please wait a moment.",
        conversation_id=conversation_id or new_id,
    )
except Exception:
    # Unexpected error
    return ChatResponse(
        response="Something went wrong. Please try again.",
        conversation_id=conversation_id or new_id,
    )
```

## Decisions Requiring ADR Documentation

### ADR-003: OpenAI SDK vs OpenAI Agents SDK for OpenRouter Integration

**Context**: Constitution says "OpenAI Agents SDK" but OpenRouter is an OpenAI-compatible REST API. The Agents SDK adds orchestration abstractions on top.

**Decision**: Use the standard OpenAI Python SDK (`openai` package) with `base_url` pointed at OpenRouter. The function-calling loop is implemented manually.

**Rationale**:
- OpenRouter is OpenAI-API-compatible, making the standard SDK the natural fit
- The Agents SDK's MCP integration expects a local MCP server process, which adds complexity without benefit here since tools are in-process Python functions
- Manual tool-call loop gives full control over user_id injection and error handling
- Migration to Agents SDK is straightforward later if needed

**Alternatives Rejected**:
- OpenAI Agents SDK: Adds unnecessary abstraction layer for this use case
- Raw HTTP requests: Loses type safety and retry logic from the SDK

### ADR-004: Server-Side user_id Injection for Tool Calls

**Context**: MCP tools require `user_id` for user isolation. The LLM could be given `user_id` in the system prompt, but this is a security risk.

**Decision**: `user_id` is never exposed to the LLM. Tool definitions omit `user_id` from parameters. The server injects `user_id` from the JWT-authenticated user when dispatching tool calls.

**Rationale**:
- Prevents prompt injection attacks where a malicious user message tricks the LLM into using a different user_id
- Follows principle of least privilege - the LLM only sees what it needs
- Consistent with constitution's Security constraint

### ADR-005: System Prompt Design

**Context**: The agent needs instructions about its role, available tools, and behavior expectations.

**Decision**: Static system prompt stored as a constant in `agent.py`. Lists tool names and descriptions, instructs the agent to confirm actions, and clarifies that `user_id` is auto-injected.

**Rationale**:
- Simple, auditable, version-controlled
- No runtime template rendering needed
- Can be promoted to a database-stored prompt later if configurability is needed

## Risk Analysis

| Risk | Likelihood | Impact | Mitigation |
|------|------------|--------|------------|
| OpenRouter API changes/downtime | Low | High | Error handling with user-friendly messages; retry logic in SDK |
| Tool-call loop infinite cycling | Low | High | Max iteration limit (e.g., 5 tool-call rounds) |
| Token limit exceeded with long history | Medium | Medium | Limit to last 50 messages; can add summarization later |
| Prompt injection via user message | Medium | High | user_id never exposed to LLM; server-side injection only |
