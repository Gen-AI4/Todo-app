# Implementation Plan: Database Schema & MCP Tool Server

**Branch**: `005-db-mcp-tools` | **Date**: 2026-02-09 | **Spec**: [spec.md](./spec.md)
**Input**: Feature specification from `/specs/005-db-mcp-tools/spec.md`

## Summary

Extend the existing FastAPI backend with chat persistence models (`Conversation`, `Message`) and implement an MCP Server with 5 task management tools (`add_task`, `list_tasks`, `complete_task`, `delete_task`, `update_task`). The MCP Server will use the official `mcp` Python SDK with `FastMCP` for tool registration. All tools enforce user isolation via `user_id` validation and return JSON-formatted responses.

## Technical Context

**Language/Version**: Python 3.11+
**Primary Dependencies**: FastAPI, SQLModel, Official MCP SDK (`mcp`/`fastmcp`), Pydantic
**Storage**: Neon Serverless PostgreSQL (existing connection via `database.py`)
**Testing**: pytest with in-memory SQLite (existing `conftest.py` pattern)
**Target Platform**: Linux server (Neon-compatible)
**Project Type**: Web application (backend-only for this spec)
**Performance Goals**: Tool operations < 500ms under normal load
**Constraints**: All tools require `user_id`, JSON string responses only
**Scale/Scope**: 5 MCP tools, 2 new models, unit tests for each tool

## Phase 1: Data Models

### 1.1 Add Conversation Model

**File**: `backend/app/models.py`

Add after User models section:

```python
class Conversation(SQLModel, table=True):
    """Conversation database model for chat history."""

    id: UUID = Field(default_factory=uuid4, primary_key=True)
    user_id: str = Field(index=True, description="Owner's user identifier")
    title: Optional[str] = Field(default=None, max_length=200)
    created_at: datetime = Field(default_factory=lambda: datetime.now(timezone.utc))
    updated_at: datetime = Field(default_factory=lambda: datetime.now(timezone.utc))


class Message(SQLModel, table=True):
    """Message database model for conversation messages."""

    id: UUID = Field(default_factory=uuid4, primary_key=True)
    conversation_id: UUID = Field(foreign_key="conversation.id", index=True)
    role: str = Field(description="Message role: user, assistant, or tool")
    content: str = Field(description="Message content")
    created_at: datetime = Field(default_factory=lambda: datetime.now(timezone.utc))
```

### 1.2 Task Model Enhancement

The existing `Task` model already has `is_completed` boolean. For MCP tools, we'll treat:
- `is_completed=False` -> status "pending"
- `is_completed=True` -> status "completed"

No schema changes needed; transformation handled in tool logic.

## Phase 3: MCP Tool Implementations

### 3.1 Tool Response Format

All tools return JSON strings with consistent structure:

**Success**: `{"success": true, "data": {...}, "message": "..."}`
**Error**: `{"success": false, "error": "error_code", "message": "..."}`

Error codes: `validation_error`, `not_found`, `unauthorized`, `internal_error`

### 3.2 Tool Implementations

Each tool follows this pattern:
1. Validate `user_id` is provided
2. Perform database operation with user isolation filter
3. Return JSON string response

### 3.3 Database Session Handling

Tools use sync context manager for database access via `Session(engine)`.
