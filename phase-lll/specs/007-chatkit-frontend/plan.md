# Implementation Plan: ChatKit Frontend Integration

**Branch**: `007-chatkit-frontend` | **Date**: 2026-02-11 | **Spec**: [spec.md](./spec.md)
**Input**: Feature specification from `/specs/007-chatkit-frontend/spec.md`

## Summary

Add a chat interface to the existing Next.js 16 frontend using the `@openai/chatkit` React component library. The chat connects to the FastAPI backend's `POST /api/chat` endpoint via a custom fetcher that injects the JWT token. The implementation uses Tailwind CSS 4 for styling and maintains conversation state locally via React state.

## Technical Context

**Language/Version**: TypeScript, React 19, Next.js 16 (App Router)
**Primary Dependencies**: `@openai/chatkit` (new), existing: Tailwind CSS 4, better-auth, swr, clsx, tailwind-merge
**Backend Endpoint**: `POST /api/chat` (from Spec 6)
**Authentication**: JWT token via better-auth (existing)
**Styling**: Tailwind CSS 4
**Testing**: End-to-end manual - type in UI, see in DB, see AI response in UI
**Constraints**: No streaming (request/response only), no custom animations
**Scale/Scope**: 1 new page component, 1 chat component, 1 API helper, auth token utility

### 2.2 Chat API Helper

**File**: `frontend/lib/api.ts` (NEW)

Custom fetch wrapper for the chat endpoint that injects JWT:

```typescript
const API_URL = process.env.NEXT_PUBLIC_API_URL || "http://localhost:8000";

export async function sendChatMessage(
  message: string,
  conversationId: string | null,
  token: string
): Promise<{ response: string; conversation_id: string }> {
  const res = await fetch(`${API_URL}/api/chat`, {
    method: "POST",
    headers: {
      "Content-Type": "application/json",
      Authorization: `Bearer ${token}`,
    },
    body: JSON.stringify({
      message,
      conversation_id: conversationId,
    }),
  });

  if (!res.ok) {
    throw new Error(`Chat request failed: ${res.status}`);
  }

  return res.json();
}
```

**Rationale**: Simple fetch wrapper rather than ChatKit's built-in fetcher because our backend uses a custom API shape (not OpenAI-compatible chat completions format). The wrapper handles JWT injection and conversation_id passing.

## Phase 3: Chat Interface Component

### 3.1 ChatInterface Component

**File**: `frontend/components/ChatInterface.tsx` (NEW)

The main chat component that:
1. Maintains local message state
2. Manages conversation_id across messages
3. Renders user messages on the right, AI on the left
4. Shows loading state while waiting for response
5. Auto-scrolls to newest message
6. Handles errors gracefully

```typescript
"use client";

import { useState, useRef, useEffect } from "react";
import { sendChatMessage } from "@/lib/api";

interface Message {
  role: "user" | "assistant";
  content: string;
}

export default function ChatInterface({ token }: { token: string }) {
  const [messages, setMessages] = useState<Message[]>([]);
  const [input, setInput] = useState("");
  const [loading, setLoading] = useState(false);
  const [conversationId, setConversationId] = useState<string | null>(null);
  const [error, setError] = useState<string | null>(null);
  const messagesEndRef = useRef<HTMLDivElement>(null);

  // Auto-scroll to bottom
  useEffect(() => {
    messagesEndRef.current?.scrollIntoView({ behavior: "smooth" });
  }, [messages]);

  async function handleSend() {
    if (!input.trim() || loading) return;

    const userMessage = input.trim();
    setInput("");
    setError(null);
    setMessages((prev) => [...prev, { role: "user", content: userMessage }]);
    setLoading(true);

    try {
      const data = await sendChatMessage(userMessage, conversationId, token);
      setConversationId(data.conversation_id);
      setMessages((prev) => [
        ...prev,
        { role: "assistant", content: data.response },
      ]);
    } catch (err) {
      setError("Unable to reach the assistant. Please try again.");
    } finally {
      setLoading(false);
    }
  }

  // Render with Tailwind styling...
}
```

**Key decisions**:
- Uses plain React state rather than ChatKit's provider since our API shape differs from OpenAI's format
- ChatKit's `<Thread>`, `<Message>`, and `<Composer>` components can be used for the UI shell if they accept custom message arrays, otherwise we build the bubble layout with Tailwind
- User messages: right-aligned, blue-ish background
- AI messages: left-aligned, gray-ish background
- Loading: pulsing dots or spinner below last message

## Decisions Requiring ADR Documentation

### ADR-006: Request/Response vs Streaming

**Context**: OpenRouter supports streaming responses. The backend (Spec 6) uses non-streaming `client.chat.completions.create()`.

**Decision**: Use request/response (non-streaming) for v1. The frontend waits for the full response and displays it at once.

**Rationale**:
- Backend currently returns complete response (no SSE/streaming endpoint)
- Simpler implementation for initial release
- Streaming can be added later by switching to SSE endpoint + EventSource on frontend
- Loading spinner provides sufficient UX feedback for <10s responses

### ADR-007: Custom Chat UI vs ChatKit Provider

**Context**: ChatKit provides a `<ChatProvider>` that manages state and connects to OpenAI-compatible endpoints. Our backend uses a custom API shape.

**Decision**: Use ChatKit's visual components (Message, Thread, Composer) where possible for styling, but manage state manually via React hooks since the backend API shape differs from OpenAI's chat completions format.

**Rationale**:
- ChatKit's provider expects OpenAI-compatible `/v1/chat/completions` streaming format
- Our backend returns `{response, conversation_id}` - a different shape
- Manual state management gives full control over conversation_id tracking and error handling
- Can migrate to ChatKit's provider later if backend adds an OpenAI-compatible proxy
