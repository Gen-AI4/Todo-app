# Implementation Plan: Chat UI Responsiveness & Modern Polish

**Branch**: `008-chat-ui-polish` | **Date**: 2026-02-11 | **Spec**: [spec.md](./spec.md)
**Input**: Feature specification from `/specs/008-chat-ui-polish/spec.md`

## Summary

Transform the existing single-panel chat UI into a responsive, theme-aware application with a desktop split view (tasks + chat), mobile tab navigation, dark/light mode support, and contextual tool-execution feedback. All changes are frontend-only using Tailwind CSS 4 and existing backend endpoints.

**Language/Version**: TypeScript, React 19, Next.js 16 (App Router)
**Primary Dependencies**: `next-themes` (installed, unused), `swr` (installed, unused), Tailwind CSS 4, `clsx`, `tailwind-merge`

**Authentication**: JWT token in localStorage (existing)
**Styling**: Tailwind CSS 4 with `@custom-variant dark` + `next-themes`
**Testing**: Chrome DevTools Device Mode — iPhone SE (375px), Pixel 7 (412px), iPad Air (820px), Desktop (1280px)
**Constraints**: No backend changes, no new npm packages, Tailwind CSS only
**Scale/Scope**: Modify 4 existing files, create 2 new component files, update 1 CSS file

## Phase 1: Mobile-First Foundation & Dark Mode Infrastructure

**Goal**: Set up the theme system, responsive CSS foundation, and make all existing components dark-mode-aware.

**Why first**: Dark mode and responsive utilities are cross-cutting concerns. Every component in later phases needs these to be in place.

### 1.1 Configure Dark Mode in globals.css

**File**: `frontend/app/globals.css`

Add Tailwind CSS 4 custom variant for class-based dark mode and base theme styles:

```css
@import "tailwindcss";

@custom-variant dark (&:where(.dark, .dark *));

html,
body {
  height: 100%;
  margin: 0;
}

body {
  font-family: system-ui, -apple-system, sans-serif;
}
```

**Rationale**: The `@custom-variant` directive enables Tailwind's `dark:` classes to respond to a `.dark` class on `<html>`, which `next-themes` manages. This replaces the default `prefers-color-scheme` behavior with class-based toggling while still supporting OS preference detection via `next-themes`'s `enableSystem` option.

### 1.2 Wrap App with ThemeProvider

**File**: `frontend/app/layout.tsx`

```tsx
import type { Metadata } from "next";
import { ThemeProvider } from "next-themes";
import "./globals.css";

export const metadata: Metadata = {
  title: "Todo AI Chatbot",
  description: "Manage your tasks through natural language conversation",
};

export default function RootLayout({
  children,
}: {
  children: React.ReactNode;
}) {
  return (
    <html lang="en" suppressHydrationWarning>
      <body className="h-full bg-gray-50 dark:bg-gray-900 text-gray-900 dark:text-gray-100">
        <ThemeProvider attribute="class" defaultTheme="system" enableSystem>
          {children}
        </ThemeProvider>
      </body>
    </html>
  );
}
```

**Key decisions**:
- `suppressHydrationWarning` on `<html>`: Required because `next-themes` injects the `class` attribute before hydration, which would cause a React mismatch.
- `defaultTheme="system"`: OS preference is the default (spec says no explicit toggle for v1).
- `enableSystem`: Reacts to OS-level `prefers-color-scheme` changes in real-time.

## Phase 2: Desktop Split-Pane Layout

**Goal**: On viewports >= 768px (`md` breakpoint), show tasks panel on the left (1/3) and chat on the right (2/3).

**Why second**: The layout structure must exist before we can build the TasksPanel component that fills the left side.

### 2.1 Create TasksPanel Component

**File**: `frontend/components/TasksPanel.tsx` (NEW)

A self-contained component that:
1. Fetches tasks from `GET /api/tasks` using `swr`
2. Displays tasks as a scrollable list
3. Shows completed tasks with strikethrough
4. Shows empty state when no tasks exist
5. Accepts a `refreshKey` prop to trigger re-fetch after chat interactions
6. Supports dark mode

```typescript
interface TasksPanelProps {
  token: string;
  refreshKey: number;  // Increment to trigger SWR revalidation
}
```

**Task item display**:
- Checkbox icon (filled for completed, empty for pending)
- Title (strikethrough if completed)
- Description (truncated, if present)
- Relative timestamp ("2m ago", "1h ago")

**Empty state**: Centered message "No tasks yet. Chat with the assistant to create some!"

**Loading state**: 3 skeleton placeholder rows (gray animated rectangles)

### 2.2 Add fetchTasks to API Helper

**File**: `frontend/lib/api.ts`

Add `TaskItem` interface and `fetchTasks()` function:

```typescript
export interface TaskItem {
  id: string;
  user_id: string;
  title: string;
  description: string | null;
  is_completed: boolean;
  created_at: string;
  updated_at: string;
}

export async function fetchTasks(token: string): Promise<TaskItem[]> {
  const res = await fetch(`${API_URL}/api/tasks`, {
    headers: { Authorization: `Bearer ${token}` },
  });
  if (!res.ok) throw new Error(`Failed to fetch tasks: ${res.status}`);
  return res.json();
}
```

## Phase 3: Mobile Tab Navigation

**Goal**: On mobile (<768px), show a bottom tab bar with "Chat" and "Tasks" tabs. Only one panel visible at a time.

**Why third**: Builds on the split layout from Phase 2. The tab bar is the mobile-specific navigation that replaces the side-by-side layout.

### 3.1 Add Tab State to Dashboard

**File**: `frontend/app/dashboard/page.tsx`

Add local state:

```typescript
const [activeTab, setActiveTab] = useState<"chat" | "tasks">("chat");
```

### 3.2 Render Tab Bar (Mobile Only)

Add a bottom tab bar visible only on mobile:

```
<div className="md:hidden flex-shrink-0 border-t ...">
  <button>Chat</button>
  <button>Tasks</button>
</div>
```

**Tab button styling**:
- Active: bold text, colored underline/background
- Inactive: muted text
- Minimum 44px height for touch targets (FR-006)
- Dark mode variants for all colors

### 3.3 Conditional Panel Rendering (Mobile)

On mobile, render both panels but show/hide based on `activeTab`:

```tsx
{/* Chat panel - always rendered, hidden on mobile when tasks tab active */}
<div className={clsx("md:w-2/3", activeTab === "tasks" && "hidden md:block")}>
  <ChatInterface ... />
</div>

{/* Tasks panel - always rendered, hidden on mobile when chat tab active */}
<div className={clsx("md:w-1/3", activeTab === "chat" && "hidden md:block")}>
  <TasksPanel ... />
</div>
```

**Critical**: Both panels are always mounted in the DOM (just hidden via CSS). This preserves chat state when switching tabs (FR-004, SC-003).

### 3.4 Mobile Input Bar Positioning

Ensure the chat input stays above the virtual keyboard on mobile:

- Use `dvh` units for the chat container height
- Input bar uses `sticky bottom-0` positioning
- Tab bar sits below the input bar (outside the chat scroll area)

## Phase 4: Tool Execution Feedback

**Goal**: Show contextual status messages ("Adding task...", "Fetching tasks...") instead of generic loading dots when a recognizable tool action is detected.

**Why last**: This is a P2 enhancement that modifies the loading indicator inside `ChatInterface`. All structural work (layout, theme) must be stable first.

### 4.1 Create Tool Feedback Utility

**File**: `frontend/lib/tool-feedback.ts` (NEW)

A pure function that maps user message text to a feedback string:

```typescript
export function getToolFeedback(message: string): string | null {
  const lower = message.toLowerCase();

  const patterns: [RegExp, string][] = [
    [/\b(add|create|new)\b.*\btask\b/, "Adding task..."],
    [/\b(list|show|what)\b.*\btask/, "Fetching tasks..."],
    [/\b(complete|finish|done|mark)\b/, "Completing task..."],
    [/\b(delete|remove)\b/, "Deleting task..."],
    [/\b(update|change|rename|edit)\b/, "Updating task..."],
  ];

  for (const [pattern, feedback] of patterns) {
    if (pattern.test(lower)) return feedback;
  }

  return null;  // No match → generic loading dots
}
```

### 4.2 Integrate Feedback into ChatInterface

**File**: `frontend/components/ChatInterface.tsx`

In `handleSend()`, before setting `loading = true`, compute the feedback:

```typescript
const feedback = getToolFeedback(userMessage);
setToolFeedback(feedback);
setLoading(true);
```

In the loading indicator section, replace the generic dots with:

```tsx
{loading && (
  <div className="...">
    {toolFeedback ? (
      <p className="text-sm text-gray-500 dark:text-gray-400 animate-pulse">
        {toolFeedback}
      </p>
    ) : (
      {/* Existing 3 bouncing dots */}
    )}
  </div>
)}
```

Clear `toolFeedback` when response arrives (in `finally` block alongside `setLoading(false)`).

## Risks & Mitigations

1. **`next-themes` flash on first load**: Mitigated by `suppressHydrationWarning` and `next-themes`'s built-in script injection. If flash persists, add `<script>` in `<head>` to set class before paint.

2. **Virtual keyboard behavior varies across browsers**: `dvh` units handle most cases. If specific devices misbehave, add `visualViewport` API as progressive enhancement.

3. **SWR cache stale after chat creates a task**: Mitigated by incrementing `refreshKey` after every chat response. Worst case: user sees stale data for one render cycle.
